# One more rule: props crossing the boundary must be data

`ExpensesTable` (Server) renders `ExpensesTableRow` (Client) with real props —
`expense`, `className`. That works because both are plain, **serializable**
values: objects, arrays, strings, numbers, booleans.

```tsx
// This is NOT allowed: a Server Component handing a function down as a prop
<ExpensesTableRow onRowClick={() => saveClickLog(expense.id)} expense={expense} />
```

- Next.js's own error is explicit about it: *"Functions cannot be passed
  directly to Client Components unless you explicitly expose it by marking
  it with `'use server'`."*
- That's exactly why `ExpensesTableRow` calls `useRouter().push(...)` **from
  inside itself**, instead of receiving an `onRowClick` function as a prop —
  the click handler has to be defined where it runs: in the Client Component.
- The exception is a **Server Action** — an async function marked
  `'use server'` — which Next.js turns into a reference it *can* serialize
  and call from the client. That's module 08's whole topic; today, just
  recognize the boundary: data crosses freely, plain functions don't.

Notes:

The error message quoted here is the real one Next.js throws — worth reading verbatim if a lab group hits it by accident (easy mistake: trying to pass an onClick down from a page.tsx). Server Actions as the sanctioned exception is a preview, not a lesson — don't build one live here, module 08 owns that.
