# React is an engine, not a car

**React** gives you the engine: components, state, rendering. It never
shipped a router, a bundler, or a way to render on the server.

**Next.js** is the whole car built around that engine: routing, server
rendering, bundling, data fetching, optimizations — all wired together
and ready to drive.

That's what **metaframework** means: a framework built _on top of_
another framework, answering the questions React leaves open.

React isn't special here — **every** UI library eventually grows a
metaframework: SvelteKit, Nuxt, Remix, Gatsby, Astro... Next.js is
simply React's.

Notes:

Emphasize this is an industry-wide pattern, not a Next.js quirk — it lowers the intimidation factor and frames Next.js as "the obvious next step after React", not a totally separate thing to learn from scratch.
